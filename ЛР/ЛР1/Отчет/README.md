#### Задание 1: Поиск 1001-го простого числа (2 балла)
- **Цель:** Найти $N$-е по счету простое число (по варианту 2: $N = 1001$).
- **Математический аппарат:** Простое число делится без остатка строго на 1 и на само себя. Числа $\le 1$ простыми не являются. Любое простое число $p > 3$ представимо в виде $6k \pm 1$. Благодаря этому оптимизированная проверка перебирает лишь треть чисел в диапазоне $[5, \lfloor\sqrt{n}\rfloor]$ с шагом 6.
- **Ключевой код ([part1.py](file:///C:/Users/ASUS/BSUIR/7%20семестр/ММО/ЛР/ЛР1/Решение/part1.py#L19-L39)):**
```python
def is_prime(n: int) -> bool:
    if n < 2: return False
    if n in (2, 3): return True
    if n % 2 == 0 or n % 3 == 0: return False
    i = 5
    while i * i <= n:
        if n % i == 0 or n % (i + 2) == 0:
            return False
        i += 6
    return True
```
- **Результат:** 1001-м простым числом является **7927**.

#### Задание 3: Анализ одномерного целочисленного списка (1 балл)
- **Цель:** Для произвольного одномерного целочисленного списка найти: 1) наибольший нечетный элемент; 2) минимальный по абсолютному значению элемент.
- **Алгоритм:**
  1. Нечетные элементы фильтруются генератором списка: `odd_elements = [x for x in L if x % 2 != 0]`, после чего применяется `max()`.
  2. Минимальный по модулю элемент находится однопроходным методом через встроенную функцию `min(actual_list, key=abs)`. Параметр `key=abs` заставляет функцию сравнивать элементы по значению $|x|$, возвращая само число $x$.
- **Результат:** Для списка `[-14, 25, 7, -3, 42, -5, 18, -2, 33, 0]` наибольший нечетный элемент равен `33`, а минимальный по модулю — `0` ($|0| = 0$).

## 4. Шпаргалка для защиты: вопросы преподавателя с подвохом и исчерпывающие ответы

### Вопрос 1: В чем фундаментальная разница между списком (List) и кортежем (Tuple) в памяти CPython?
- **Ответ:**
  1. **Структура в C:** Список реализован через структуру `PyListObject`, которая содержит указатель на массив указателей `ob_item` и два счетчика: `ob_size` (число элементов) и `allocated` (выделенная память). Кортеж (`PyTupleObject`) содержит фиксированное количество указателей прямо в теле самого объекта.
  2. **Механизм over-allocation:** Чтобы метод `.append()` работал за амортизированное время $O(1)$, CPython выделяет списку память «с запасом» по специальной формуле:
     $$\text{allocated} \approx \text{new\_size} + (\text{new\_size} \gg 3) + (\text{new\_size} < 9 \,?\, 3 : 6)$$
     Кортеж никогда не выделяет лишней памяти — он занимает ровно столько байт, сколько нужно его элементам.
  3. **Хешируемость:** Кортеж неизменяем, поэтому значение его хеш-функции вычисляется один раз и не может измениться. Это позволяет использовать кортежи в роли ключей словарей (`dict`) и элементов множеств (`set`). Список изменяем, поэтому попытка вызвать `hash([])` приводит к ошибке `TypeError: unhashable type: 'list'`.

### Вопрос 2: Как устроен механизм try-except-else-finally и выполнится ли finally при return?
- **Ответ:**
  1. Блок `try` запускает выполнение кода.
  2. Если внутри возникло исключение, интерпретатор прерывает выполнение и ищет подходящую ветку `except`.
  3. Ветка `else` выполняется **только тогда**, когда блок `try` завершился штатно без единого исключения.
  4. Ветка `finally` выполняется **всегда и гарантированно**!
  5. **Подвох с `return`:** Даже если внутри блока `try` или `except` стоит инструкция `return`, CPython сохраняет возвращаемое значение во временном регистре виртуальной машины, **обязательно выполняет код блока `finally`**, и только затем фактически выходит из функции. Более того, если внутри блока `finally` написать собственный `return 999`, он перезапишет возвращаемое значение из `try`!

---

### Вопрос 3: В чем разница между атрибутом класса и атрибутом экземпляра и что происходит при записи через self?
- **Ответ:**
  - **Атрибут класса (статическая переменная):** Создается в теле класса и хранится в `Class.__dict__`. Он является общим для всех объектов данного класса.
  - **Атрибут экземпляра (динамическая переменная):** Создается через `self.field = val` и хранится в `instance.__dict__` конкретного объекта.
  - **Подвох с затенением (Shadowing):** Если у нас есть атрибут класса `a = 100`, и мы выполняем чтение `print(instance.a)`, Python сначала ищет `a` в `instance.__dict__`. Не найдя его там, он поднимается в `Class.__dict__` и выводит `100`. Но если мы напишем `instance.a = 500`, Python **не изменит атрибут класса**, а создаст новый одноименный динамический атрибут в словаре данного конкретного объекта! Атрибут класса `Example.a` останется равен `100`.

### Вопрос 4: Чем отличаются instance method, @classmethod и @staticmethod?
- **Ответ:**
  - **Обычный метод экземпляра (`instance method`):** Первым аргументом неявно принимает `self` (указатель на экземпляр). Имеет доступ к полям объекта и может менять его состояние.
  - **Метод класса (`@classmethod`):** Первым аргументом неявно принимает `cls` (указатель на сам объект-класс, а не на экземпляр). Имеет доступ к атрибутам класса и используется для альтернативных фабричных конструкторов (`from_csv`, `from_json`).
  - **Статический метод (`@staticmethod`):** Не принимает ни `self`, ни `cls`. Это обычная изолированная функция, логически помещенная внутрь пространства имен класса для лучшей модульности. Она не может напрямую изменять состояние экземпляра или класса.

### Вопрос 5: Как работает сборщик мусора в CPython и для чего нужен Global Interpreter Lock (GIL)?
- **Ответ:**
  1. **Подсчет ссылок (Reference Counting):** Главный механизм управления памятью. Каждый объект CPython содержит заголовок `PyObject_HEAD` с полем `ob_refcnt`. Когда на объект создается новая ссылка, счетчик увеличивается; когда переменная выходит из области видимости или удаляется через `del`, счетчик уменьшается. При падении `ob_refcnt == 0` память освобождается мгновенно.
  2. **Циклический сборщик мусора (Generational Garbage Collector):** Нужен для борьбы с циклическими ссылками (когда объект $A$ ссылается на $B$, а $B$ на $A$, и счетчик никогда не станет 0). Сборщик делит объекты на 3 поколения (0, 1, 2) и периодически ищет изолированные графы циклических ссылок, удаляя их.
  3. **GIL (Global Interpreter Lock):** Глобальная блокировка интерпретатора CPython. Так как управление счетчиками ссылок `ob_refcnt` не является потокобезопасным, GIL разрешает исполнять байт-код Python только одному системному потоку одновременно на одном ядре процессора, предотвращая состояние гонки при управлении памятью.
